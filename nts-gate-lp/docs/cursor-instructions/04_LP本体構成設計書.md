# 04｜自動生成LP 本体構成設計書（profits-ops 品質）

## 目的
クローリングで取得した補助金制度情報を流し込んで生成される個別LP（例: `/subsidies/lp/[id]`）を、現状の「制度概要ページ」から **profits-ops.com 同等のLPクオリティ** に引き上げる構成設計。
本ファイルはセクション順・要素仕様・データバインディングまで定義し、Cursor が実装に着手できる粒度を担保する。

> 参照すべき補助文書:
> - `03_デザイントークン定義.md`（カラー・余白・モーション）
> - `02_ガイドカード_視認性修正.md`（ライブラリのカード）
> - 既存 `nts-gate-lp/docs/会社入力型補助金マッチング_設計書.md`（マッチング導線）

---

## 0. 全体方針

### 0.1 デザイン哲学（profits-ops から借用）
- **structured / tokenized / content-first**: 飾りではなく構造で見せる
- **オフセット影**（5px 5px 0 0 rgba(0,0,0,0.05)）でカードに浮遊感
- **ダーク基調 + ライトセクションの交互配置** でリズム
- **数字を主役にする**（補助上限・補助率・締切）
- **マイクロインタラクション**（カウントアップ・スクロール連動）

### 0.2 出口（CTA）の三層設計
1. **メインCTA**: `無料相談を予約する`（オレンジ・第二アクセント）
2. **サブCTA**: `自社で対象か診断する`（30秒チェック・第一アクセント・ティール）
3. **回避CTA**: `他の補助金を見る` / `関連解説記事を読む`（スルーされても接点を残す）

### 0.3 セクション全体構成（縦の流れ）

```
1. Hero（強化版）
2. ⚡ 30秒対象診断
3. 数字で見る制度規模（KPIカード）
4. こんな企業が活用しています（ペルソナ3パターン）
5. 申請から入金までの流れ（タイムライン）
6. よくある不安TOP3（不安→回答→次の一歩）
7. 当社の強み（伴走支援の差別化）
8. 関連する解説記事（内部リンク）
9. 最終CTA + フッター上部
```

各セクションの推奨高さ・余白は `--space.20` 〜 `--space.24` を縦に取る。

## 1. Hero セクション（強化版）

### 1.1 目的
補助金の「**規模感**」と「**残された時間**」を3秒で伝え、CTAへ誘導する。

### 1.2 レイアウト
2カラム（PC）/ 1カラム積み（SP）。左7：右5。

```
┌─────────────────────────────────┬──────────────────┐
│ SUBSIDY ACTION GUIDE / 残N日タグ                                │ 浮遊カード        │
│                                                                                       │ FREE CONSULTATION │
│ 補助金カテゴリ（小見出し）                                              │ 自社で使えるか、 │
│                                                                                       │ まずは無料で確認  │
│ ## 大型タイトル（H1）                                                       │                                │
│                                                                                       │ KPIテーブル        │
│ サブコピー                                                                       │ - 補助上限         │
│                                                                                       │ - 補助率           │
│ TARGET SUBSIDY ボックス                                                  │ - 公募期限         │
│ [補助金正式名称]                                                            │ - 対象地域         │
│                                                                                       │                                │
│ [無料相談する →] [制度概要を見る]                                  │ [無料相談を予約]│
│ #相談無料 #公募要領で最終確認 #申請後も伴走支援          │                                │
└─────────────────────────────────┴──────────────────┘
```

### 1.3 構成要素と仕様

| 要素 | 仕様 |
|---|---|
| 上部タグ群 | `SUBSIDY ACTION GUIDE`（小キャッチ）+ `締切まで残り N 日`（**N が30以下なら警告色 `--color.accent.secondary`**） |
| カテゴリ | `事業再構築補助金` 等。`--color.accent.cyan` |
| H1 | 制度のメッセージ。最大3行。`font.size.3xl` / weight.bold / leading.tight |
| サブコピー | 90〜140字。`font.size.md` / `--color.text.secondary-on-dark` |
| TARGET SUBSIDY | 制度正式名称を枠内に。`background: rgba(255,255,255,0.04)` / `radius.md` / padding 16-20px |
| メインCTA | オレンジボタン。`bg: --color.accent.secondary` / `radius.full` / padding 14×32 / hover で `glow.orange` 影 |
| サブCTA | アウトラインボタン。`border: 1px solid rgba(255,255,255,0.3)` |
| 信頼チップ | 3つ並列。`bg: rgba(255,255,255,0.06)` / `radius.full` |
| 浮遊カード | profits-ops 風。**オフセット影 `--shadow.offset` 適用**。中身は KPI 4項目 + 大型CTA |

### 1.4 動的演出（必須）
- 補助上限の数値は `0円 → 最大1.5億円` に **1400ms でカウントアップ**（`IntersectionObserver` で初回表示時）
- `締切まで残り N 日` は毎ページロードで日次計算
- ヒーロー全体に薄いグラデーション（左上から右下にかけて `rgba(255,255,255,0.02)` の照射）

### 1.5 データバインディング
```ts
hero: {
  category: subsidy.category,        // 例: "事業再構築補助金"
  title: subsidy.heroTitle,          // 例: "新しい事業への挑戦を、資金面から前に進めるための制度です"
  subtitle: subsidy.heroSubtitle,
  fullName: subsidy.officialName,    // TARGET SUBSIDY 表示
  deadline: subsidy.deadline,        // ISO日付
  daysLeft: computeDaysLeft(deadline),
  maxAmount: subsidy.maxAmount,      // "150,000,000"
  maxAmountLabel: subsidy.maxAmountLabel, // "最大1.5億円"
  rate: subsidy.subsidyRate,         // "要確認" or "2/3"
  region: subsidy.region,            // "全国"
}
```

## 2. ⚡ 30秒対象診断セクション（新設・最重要）

### 2.1 目的
インタラクティブ要素でスクロール深度を底上げし、自分ごと化させる。同時にリードクオリフィケーションを兼ねる。

### 2.2 レイアウト
中央寄せ・最大幅 `880px` のカード。背景はダーク基調。

```
┌───────────────────────────────────────────┐
│ 30 SEC CHECK                                                                  │
│                                                                                              │
│ ## あなたの会社は、この補助金の対象ですか？                          │
│                                                                                              │
│ □ 売上が10%以上減少している、または将来的なリスクを感じている │
│ □ 新規事業 / 業態転換 / DX投資を検討している                          │
│ □ 中小企業または中堅企業である                                                │
│                                                                                              │
│ → 該当数に応じて結果が即座に表示                                          │
│   3つ該当: ✅ 対象の可能性大 → [無料相談する]                           │
│   2つ該当: ⚠️ 詳細確認推奨 → [専門家に質問する]                       │
│   1つ以下: ℹ️ 別の補助金が向いているかも → [他制度を見る]         │
└───────────────────────────────────────────┘
```

### 2.3 仕様
- 各チェックボックス: 大型（24×24px）/ ラベルクリックでも反応 / アニメーション 200ms
- 結果表示は同一カード内に下に展開（`max-height` トランジション）
- 結果ごとに表示するCTAを切り替える
- セクション全体: `padding: 80px 0`

### 2.4 注意
- 設問は補助金カテゴリごとに切り替わる必要あり → データに `eligibilityChecks: [{q, weight}]` を持たせる
- 既存 `docs/設問設計書.md` の設問体系と整合させる

## 3. 数字で見る制度規模（KPIカード4枚）

### 3.1 目的
スキャナブルに「規模・条件・期限・範囲」を伝える。

### 3.2 レイアウト
4カラム（PC）/ 2×2（タブレット）/ 1カラム（SP）。

各カードはライト背景セクション内に配置し、**オフセット影 `--shadow.offset`** を効かせて浮かせる。

```
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│ 補助上限    │  │ 補助率       │  │ 締切まで    │  │ 対象地域    │
│ 最大        │  │              │  │              │  │              │
│ 1.5億円    │  │ 2/3          │  │ 167日       │  │ 全国        │
│ ↑カウントアップ│ │              │  │              │  │              │
└──────────┘  └──────────┘  └──────────┘  └──────────┘
```

### 3.3 各カード仕様
- 背景: `#FFFFFF` / 角丸 `radius.lg` / padding 24px
- 影: `--shadow.offset`（オフセット影）
- ラベル: `font.size.sm` / `--color.text.tertiary-on-light`
- 数値: `font.size.4xl` / `font.weight.black` / `font.family.numeric`
- 数値色: `--color.text.primary-on-light`
- アイコン（任意）: 左上にアウトラインアイコン20px

### 3.4 演出
- スクロールでセクションが入ったら一斉にカードがフェードイン（`stagger 80ms`）
- 数値はカウントアップ
- hoverで `translateY(-3px)` + 影を `--shadow.lg` に切り替え

## 4. こんな企業が活用しています（ペルソナ3パターン）

### 4.1 目的
具体例で自分ごと化させる。「使ったら何ができたか」を見せる。

### 4.2 レイアウト
3カラム横並び（PC）/ カルーセル（SP）。

各ペルソナカード:
```
┌────────────────────────┐
│ [業種アイコン]                                │
│ 製造業 / 従業員50名                       │
│                                                        │
│ 課題: 既存事業の利益率低下                   │
│ 投資: 新工場ライン導入                          │
│ 補助額: 3,000万円                                │
│                                                        │
│ ─────────────                              │
│ 「申請までの伴走で安心して動けた」     │
└────────────────────────┘
```

### 4.3 仕様
- 背景: ダークセクション内であれば `--color.bg.card`、ライトセクションなら `#FFFFFF`
- 角丸: `radius.lg` / padding 28px
- ヘッダーアイコン: ブランドカラーのモノクロイラスト（公式素材）
- 補助額の数値: 数値フォント / `font.size.xl` / `font.weight.bold`
- 引用文: italic / `font.size.sm` / 引用符を装飾的に配置

### 4.4 データ
```ts
personas: [
  { industry: "製造業", scale: "従業員50名", challenge, investment, amount, quote },
  { industry: "飲食業", scale: "店舗5店", ... },
  { industry: "サービス業", scale: "個人事業", ... },
]
```
※ 補助金カテゴリごとに3パターン用意。架空例の場合は **「※想定事例です」と必ず注記**。

## 5. 申請から入金までの流れ（タイムライン）

### 5.1 目的
複雑そうに見える申請プロセスを"5〜7ステップで分かる"に翻訳する。

### 5.2 レイアウト
PCは横タイムライン（スクロール連動で線が伸びる）/ SPは縦タイムライン。

ステップ例（事業再構築の場合）:
1. **事前準備** — 事業計画の整理（1〜2週間）
2. **公募申請** — 申請書類提出（締切までに）
3. **採択発表** — 約2〜3ヶ月後
4. **交付申請** — 採択後に詳細申請
5. **事業実施** — 補助対象期間内で実施
6. **実績報告** — 完了後の報告書提出
7. **補助金入金** — 報告書受理後

### 5.3 仕様
- 各ステップ: 番号バッジ（円形・ティール塗り）+ タイトル + 期間 + 一行説明
- 線: `IntersectionObserver` で `width: 0 → 100%` トランジション
- 現在ステップを**強調**する仕掛け（オプション。診断結果と連動可能）

## 6. よくある不安TOP3（不安→回答→次の一歩）

### 6.1 目的
申請ハードルを下げる。FAQの羅列ではなく**1枚で完結する不安解消ストーリー**。

### 6.2 レイアウト
3カラム（PC）。各カード内に「不安」→ 矢印 →「回答」→ 「次の一歩CTA」を縦に配置。

```
┌────────────────┐
│ 😟 不安                                  │
│ "申請が複雑そう..."          │
│                                                │
│ ↓                                              │
│                                                │
│ 💬 回答                                  │
│ 専門家が公募要領の最終確認│
│ から書類作成まで伴走します。 │
│                                                │
│ → [無料相談する]                  │
└────────────────┘
```

### 6.3 標準3項目（カテゴリにより差し替え可）
1. 申請が複雑そう → 専門家伴走 → 無料相談
2. 採択されるか不安 → 事前に勝率診断 → 30秒診断にスクロール
3. 費用がいくらかかる → 成功報酬中心 → 料金を見る

## 7. 当社の強み（差別化セクション）

### 7.1 目的
「なぜNTSなのか」を3〜4要素で示す。

### 7.2 レイアウト
4カラム（PC）/ 2×2（タブレット）/ 1カラム（SP）。各要素にアイコン+短文。

例:
- ✅ 採択率 ●●%（業界平均の1.5倍）
- 🤝 申請後の伴走支援（実績報告までフォロー）
- 📋 公募要領の最終確認（要件漏れを防ぐ）
- 🌏 全国対応（オンライン完結）

### 7.3 仕様
- 各要素のアイコン: 単色塗り（アクセントカラー）/ 32px
- タイトル: `font.size.lg` / `font.weight.bold`
- 説明: `font.size.sm` / 2〜3行
- 各要素はカード化せず、グリッドのみで並べる方が"装飾過多"を避けられる

relatedArticles: Article[]  // 同タグの記事3-4本を関連度順

## 9. 最終CTA + フッター上部

### 9.1 目的
スクロール離脱直前で再訴求。ヒーローと違うアプローチ。

### 9.2 レイアウト
フルブリード・ダーク基調・中央寄せ。

```
              締切まで残り 167 日

           ## 自社で使えるか、まずは確認から。

   制度の対象範囲・補助率・必要書類は、無料相談で個別に整理できます。

         [無料相談を予約する] （巨大ボタン・オレンジ）

           [対象補助金を確認する] （サブ）
```

### 9.3 仕様
- 残日数を再表示（30日以下なら警告色＋点滅なしのパルス）
- 巨大ボタン（高さ64px / 横幅は最大400px / radius.full / `--shadow.glow.orange` 常時）
- 補助テキスト: `font.size.md` / `--color.text.secondary-on-dark`

### 9.4 スティッキー要素（オプション）
SP（モバイル）では画面下部に**スティッキーCTAバー**を常時表示:
```
[ 無料相談 ]   [ 30秒診断 ]
```
スクロール量が画面の30%を超えたらスライドインで表示。

## 10. アニメーション仕様まとめ

| 要素 | きっかけ | アニメーション | duration |
|---|---|---|---|
| ヒーローのKPI数値 | 初回ビューイン | カウントアップ | 1400ms |
| KPIカード | スクロールでビューイン | フェード+5pxアップ（stagger 80ms） | 600ms |
| タイムライン線 | スクロール連動 | 横0→100% | 連動 |
| カードhover | hover | translateY(-2px) + 影深く | 240ms |
| ボタンhover | hover | グロー影 + 背景濃く | 200ms |
| 矢印（CTA） | hover | translateX(4px) | 200ms |

`prefers-reduced-motion: reduce` 時はすべて即時表示にフォールバック（必須）。

## 11. データスキーマ（クローリング → LP生成）

```ts
type SubsidyLP = {
  // Hero
  id: string;
  category: string;
  officialName: string;
  heroTitle: string;
  heroSubtitle: string;
  deadline: string;       // ISO
  maxAmount: number;
  maxAmountLabel: string; // "最大1.5億円"
  subsidyRate: string;    // "2/3" or "要確認"
  region: string;

  // Diagnostic
  eligibilityChecks: { q: string; weight: number }[];

  // Personas
  personas: {
    industry: string;
    scale: string;
    challenge: string;
    investment: string;
    amount: string;
    quote: string;
  }[];

  // Timeline
  applicationSteps: {
    step: number;
    title: string;
    duration: string;
    description: string;
  }[];

  // FAQ-as-Story
  concerns: {
    icon: string;
    worry: string;
    answer: string;
    cta: { label: string; href: string };
  }[];

  // Strengths
  strengths: { icon: string; title: string; description: string }[];

  // Related
  relatedArticleIds: string[];
};
```

クローリング段階で取得が難しいフィールド（personas, concerns）は **カテゴリ別テンプレート** から自動補完するパイプラインを推奨。

## 12. テンプレート切り替えロジック

補助金カテゴリ別に5パターンのプリセットを推奨:
1. 事業再構築系（大型投資・複雑申請）
2. ものづくり補助金系（設備投資中心）
3. IT導入補助金系（DX・SaaS導入）
4. 持続化補助金系（小規模事業者向け）
5. 雇用・人材系（教育訓練系）

カテゴリで切り替わるのは:
- ペルソナ3パターン
- 申請タイムラインのステップ数
- 強みセクションの訴求軸
- 関連記事タグのフィルタ条件

---

## 13. アクセプタンス基準（ページ全体）

- [ ] Lighthouse Performance 80+ / Accessibility 95+
- [ ] LCP（ヒーロー読み込み）2.5s以内
- [ ] 全インタラクティブ要素にfocus-visibleが効く
- [ ] `prefers-reduced-motion: reduce` で全アニメ停止
- [ ] スクリーンリーダーで上から自然に読み上げられる
- [ ] モバイル375px幅で崩れがない
- [ ] スティッキーCTAバー（モバイル）が表示・非表示を適切に切り替え
- [ ] 9セクションすべてが存在し、各セクション間に視覚的リズム（ダーク↔ライト交互配置）がある
- [ ] 数値カウントアップが初回ビューインで動く
- [ ] 30秒診断のチェック数に応じてCTAが切り替わる

---

## 14. アンチパターン

- 全セクションが同じダーク背景でリズムがない
- カードに影もボーダーもなく、平面的
- 数値が小さく、本文と区別がない
- CTAが1種類しかなく、緊急性が伝わらない
- ペルソナが架空のステレオタイプで信用されない（必ず`※想定事例`と注記）
- アニメーションが派手すぎてコンテンツを邪魔する

---

## 15. 段階リリース計画（推奨）

| フェーズ | スコープ | 期間目安 |
|---|---|---|
| Phase 1 | Hero強化 + KPIカード + 最終CTA | 3日 |
| Phase 2 | 30秒診断 + タイムライン | 4日 |
| Phase 3 | ペルソナ + 不安TOP3 + 強み | 3日 |
| Phase 4 | 関連記事 + スティッキーCTA + アニメーション最終調整 | 2日 |

**まず Phase 1 で1本だけ完成版を作り、品質を確認してからテンプレ化** する方針を推奨。
