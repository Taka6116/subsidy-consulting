# HyperFrames方式 個別補助金LP動画生成 設計指示書

## 目的

個別補助金LPごとに、LPの内容と一貫した説明動画を自動生成する。

現在のFFmpegスライド方式は、静止画を順番に見せる構造のため「紙芝居感」が強い。今後はHyperFrames OSSを用いて、HTML/CSS/JSベースのモーショングラフィック動画として生成し、LPと同じ情報・配色・トーンを持つ説明動画に置き換える。

## 前提

- HyperFramesはOSS版を利用する。
- HyperFrames Cloud API、HeyGen本体、Veo等の有料AI動画APIは使わない。
- Vercel上で動画レンダリングは行わない。
- 動画生成はローカル、バッチワーカー、または将来的な専用サーバーで実行する。
- 完成したMP4のみをS3または既存の動画保存先に保存し、LPから参照する。

## 対象データ

動画生成には、個別補助金LPで使用している構造化データを使う。

- 補助金ID
- 補助金名
- ヒーローコピー
- サブコピー
- 補助上限額
- 補助率
- 公募期限
- 対象地域
- 課題リスト
- 活用イメージ3件
- FAQまたは不安解消コピー
- CTA文言
- 関連LP URL

既存の `buildSubsidyLpData` 相当の出力を動画用JSONとして流用する。

## 動画構成

標準尺は約60秒とする。

| Scene | 秒数 | 目的 | 主な表示内容 |
| --- | ---: | --- | --- |
| Hook / 課題提示 | 0〜6秒 | 自社の話だと感じてもらう | 課題ベースのメインコピー、制度名小表示 |
| 制度概要 | 6〜15秒 | 数字と条件を短く理解してもらう | 補助金名、補助上限、補助率、締切 |
| 課題整理 | 15〜25秒 | LPのProblemを動画化する | 課題3件、ISSUE表記 |
| 活用イメージ | 25〜43秒 | LPのUse Casesと一貫した説明 | persona、label、body要約を3件 |
| 申請の流れ | 43〜52秒 | 行動への不安を下げる | 事前確認、申請準備、採択後対応、実績報告、入金 |
| CTA | 52〜60秒 | LPまたは無料相談へ誘導する | 無料相談CTA、NTSロゴ、LP URL |

## 音声・ナレーション設計

動画は無音のモーショングラフィックではなく、内容に合った音声ナレーション付きの説明動画とする。視聴者が音声だけでも制度概要と次の行動を理解できる状態を目指す。

### 音声生成の前提

- ナレーション原稿はLPデータから自動生成する。
- 補助金名、補助上限、補助率、締切、課題、活用イメージ、CTAを含める。
- 映像シーンごとにナレーション文を分ける。
- 1本あたり約60秒を標準とする。
- TTSは既存の音声生成基盤を優先して使う。
- 新たに有料AI動画APIは使わない。

### 推奨TTS

既存の動画生成で使っている音声生成方式を優先する。

- AWS Polly
- 既存のElevenLabs連携が有効な場合はElevenLabs

初期実装では、すでにコードベースにあるTTS処理を再利用する。

### ナレーション構成

| Scene | ナレーション例 |
| --- | --- |
| Hook | 燃料費や設備投資の負担が増えるなか、使える補助金を見落としていませんか。 |
| 制度概要 | この制度では、対象となる設備投資について、補助上限や申請期限を確認しながら活用を検討できます。 |
| 課題整理 | 軽油価格の高騰、環境対応、老朽化した設備の更新。こうした課題を、投資計画として整理することが重要です。 |
| 活用イメージ | たとえば土木工事業では電動ショベルの導入、解体工事業では低騒音重機への切り替えなどが考えられます。 |
| 申請の流れ | 申請前には、対象要件、補助対象経費、締切を確認し、事業計画として整理します。 |
| CTA | 自社で使えるか分からない場合は、まず無料相談で確認できます。日本提携支援が、制度選びから活用設計まで伴走します。 |

### ナレーション生成ルール

- 各シーンの尺に収まる文字数にする。
- 1秒あたり日本語5〜7文字程度を目安にする。
- 長すぎる補助金名は全文を毎回読ませない。
- 「採択されます」「必ず使えます」などの保証表現は禁止。
- 「架空」「想定事例」「実際の採択事例ではありません」などの表現は禁止。
- 補助金の制度条件は入力データに基づく。
- 不明な条件は「公募要領で確認が必要です」と表現する。
- CTAでは「申請代行」ではなく「活用設計・伴走支援」と表現する。

## 字幕設計

- ナレーションに合わせて字幕を表示する。
- 字幕は全文ではなく、要点を短く出す。
- 1字幕あたり20〜28文字程度を目安にする。
- 画面下部に白背景または半透明ネイビー背景で表示する。
- 重要な数字は字幕でも強調する。

## 音声ファイル生成・同期

処理手順:

1. LPデータから動画用JSONを生成する。
2. 各シーンの `voiceover` を生成する。
3. TTSで音声ファイルを生成する。
4. HyperFramesで映像をレンダリングする。
5. FFmpegで映像と音声を合成する。
6. 完成MP4を保存する。

音声生成に失敗した場合は動画生成を失敗扱いにし、無音動画として公開しない。

## 技術構成

### 新規ディレクトリ

- `src/lib/video-hyperframes/`
  - `buildVideoData.ts`
  - `validateHyperframesVideoData.ts`
  - `renderHyperframesVideo.ts`
  - `templates/subsidy-lp-video/`

### 役割分担

- HyperFrames: 映像生成
- 既存TTS: ナレーション音声生成
- FFmpeg: 映像と音声の最終合成
- S3: MP4/音声/サムネイル保存
- GeneratedContent: 生成動画のメタデータ保存

## 既存動画生成との関係

当面は既存のFFmpeg動画生成を残す。HyperFrames方式は新しい生成方式として追加し、品質確認後に標準方式へ切り替える。

- `VIDEO_RENDERER=ffmpeg`
- `VIDEO_RENDERER=hyperframes`

初期導入時は `hyperframes` を手動または一部補助金のみで試す。

## 品質ガードレール

動画生成前に以下を検証する。

- 活用イメージが3件ある。
- 「架空」「想定事例」「実際の採択事例ではありません」を含まない。
- 各シーンにナレーションがある。
- CTAが必ず含まれる。
- 総尺が45〜75秒に収まる。
- 1シーンあたりの文字数が多すぎない。
- 補助金名と無関係な業種が出ていない。

検証に失敗した場合は動画生成しない。AI再生成またはフォールバックコピーで補完する。

## 非目標

- 実写風AI動画の生成
- VeoやHeyGen有料APIの利用
- Vercel Function内での動画レンダリング
- 補助金制度にない数値や成果の創作
- 毎回異なる映像演出をAIに自由生成させること

## 成功条件

- 紙芝居ではなく、LPの内容を動く説明動画として見せられる。
- 補助金ごとにコピーと数字が自動で差し替わる。
- 内容に合った音声ナレーションが入る。
- 字幕が入り、音声なしでも概要が分かる。
- 活用イメージが必ず3件表示される。
- LPと動画のトーンが一致している。
- 有料会員登録なしで生成できる。
- 1本あたり約60秒のMP4を安定生成できる。
