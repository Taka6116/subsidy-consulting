# 補助金個別LP 品質ガードレール設計書

## 目的

補助金データが薄い、またはJGrants由来の表示値が冗長な場合でも、個別LPの品質を一定以上に保つ。

特に以下を防ぐ。

- 対象地域に47都道府県がすべて表示され、カードやKPIが崩れる
- 制度と関係のない固定業種ラベルが表示される
- `description` や `targetIndustries` が空のときに汎用的なコピーへ逃げる
- 建設機械向け補助金に「小売・飲食業」など不一致な活用例が出る
- `要確認` が多くなり、LPの説得力が落ちる

## 対象

- `src/lib/subsidy-lp/buildSubsidyLpData.ts`
- `src/lib/ai/bedrockLpGenerate.ts`
- `src/components/subsidy-lp/SubsidyLpUseCases.tsx`
- `src/lib/content/runLpJob.ts`

## データ正規化ルール

### 対象地域

- `全国` を含む場合は `全国` と表示する。
- 47都道府県に近い数が列挙されている場合は `全国` と表示する。
- 80文字を超える地域表示はカード内に出さず、`複数地域（詳細は公募要領で確認）` に丸める。
- LP本文では、必要に応じて公募要領確認の注記で補足する。

### 補助上限

- `rawPayload.subsidy_max_limit` が正の数値なら最優先する。
- 金額が大きい場合は `最大 14.3億円` のように短く表示する。
- 不明な場合は `要確認` にし、金額を創作しない。

### 補助率

- 数値が取れる場合のみ表示する。
- 不明な場合は `要確認` とし、AIに推定させない。

## コピー生成ルール

### 業種推定

`description` や `targetIndustries` が空でも、制度名から対象業種を推定する。

- 建設機械・重機・ショベル・解体: 土木工事業、解体工事業、建設会社、建機レンタル会社
- 商用車・物流・配送: 運送業、物流会社、配送事業者、食品卸
- 電動化・脱炭素: 燃料費、排ガス、騒音、環境対応、設備更新
- 事業再構築: 新規事業、業態転換、設備投資、販路拡大
- DX・IT: 業務効率化、紙管理脱却、受発注管理、在庫管理

### 活用事例

- 固定の業種ラベルは禁止。
- 各useCaseには `persona` を持たせる。
- `persona` は制度名と一致する業種・状況にする。
- `body` は「この補助金をどう使えるか」の活用パターンとして書き、成果数値の断定は禁止。
- 制度と無関係な業種を出さない。

### FAQ

- 制度固有の論点を1つ以上含める。
- 不明な条件は断定せず、公募要領確認に寄せる。

## 表示ルール

- Use Casesカード上部の業種表示はAI生成の `persona` を使う。
- `persona` がない既存データでは `活用イメージ` を表示する。
- 長すぎる地域・所管機関名はカードやKPIで表示崩れを起こさないように丸める。

## 品質チェック観点

- `targetArea` が80文字を超えていないこと
- `useCases.persona` が制度名と矛盾していないこと
- 建設機械LPに小売・飲食・ITなどの無関係ラベルが出ないこと
- `要確認` がLP全体で過剰に目立たないこと
- `heroCopy` と `subCopy` が制度名の語句だけに依存した汎用文になっていないこと

## 運用

LPを再生成する場合は `force: true` で `POST /api/lp/generate` を呼び出す。

再生成後は以下を確認する。

- `/subsidies/lp/[subsidyId]` が200で表示される
- 対象地域が `全国` または短い表示になっている
- 活用事例のpersonaが制度内容と一致している
- 既存のLPテンプレートのデザインが崩れていない
